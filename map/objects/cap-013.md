# cap-013 — Persistent project workspaces

A research project is a folder on disk with a CLAUDE.md (identity + routing), an outputs/ subdir for per-run artifacts, a references/ subdir for stable factory material, and a templates/ subdir for the stamps. The folder survives across sessions and crons; future agents open it cold and walk it via CLAUDE.md.

## Why this shape

This repo *is* a persistent project workspace. The pattern was formalized as ICM (Interpretable Context Methodology) by Van Clief + McDermott (arXiv:2603.16021) and adapted for Hermes as the `icm-workspace-design` skill (`/opt/data/skills/research/icm-workspace-design/`). cap-013 is the explicit codification of the pattern as a shipping capability — every recurring research workflow (this brainstorm, the ICM weekly digest, future client-intake work) should land in its own workspace, not in the global `/opt/data/digests/` or `/opt/data/handoffs/`.

## Shape

- **Workspace schema**: per the `icm-workspace-design` skill, six forms (Pipeline / Umbrella / Record library / Knowledge bundle / Context map / System map)
- **Selection**: form chosen by the repeating unit of work (run, several runs sharing identity, record, knowledge, organization, folder-for-editing)
- **Location**: `/opt/data/workspaces/<topic>/` (new convention, parallel to `/opt/data/digests/` for one-off digests)
- **Lifecycle**: created on Phase 3 SHIP decision; archived when the project closes (folder renamed to `_archive/<topic>-<closed-at>/`)

## Connected to

- **owns:** the convention that recurring research workflows get their own workspace folder under `/opt/data/workspaces/<topic>/`
- **owned-by:** the `icm-workspace-design` skill (`/opt/data/skills/research/icm-workspace-design/`) — this card is the *delivery* of that skill into the capability set
- **joins:** `cap-014` (Shadow agent CRUD — operates on its own notes, lives *inside* a workspace); every Phase 4 capability that ships a skill or MCP server (each becomes a workspace)
- **looks-like-but-is-not:** the `/opt/data/digests/` directory (that's a *record library* form, already works as a flat archive; workspaces are scoped, typed, and have a workspace-life separate from per-run digests)

## If you change this

- **Hits:** the `/opt/data/workspaces/` directory convention; the `icm-workspace-design` skill's adoption rate; every future Phase 4 SHIP that lands in a workspace; the `cron-job-health-audit` skill (it reads workspace folders too, per the Phase 1 restructure)
- **Does not hit:** `/opt/data/digests/` (separate concern — record library form); existing skill directories under `/opt/data/skills/` (different namespace, different lifecycle); `/opt/data/handoffs/` (those are session-scoped handoff docs, not project workspaces)
