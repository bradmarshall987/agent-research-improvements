# cap-010 — Mandatory scope card before any research run

Before any research workflow fires (cron or ad-hoc), it produces a one-page **scope card**: research question, success criteria, expected output shape, time budget, and which capabilities from this repo will be used. The workflow cannot proceed until the scope card is acknowledged — by Dan for cron-driven workflows, by the user for ad-hoc.

## Why this shape

The 2026-08-30 distillation surfaced "scope drift" as a recurring failure mode: a research run starts with a clear question, drifts into adjacent topics, and ends with a digest that doesn't match what Dan asked for. A scope card at the *start* forces articulation and gives Dan a checkpoint to redirect before 30+ minutes of API spend. It's the human gate before the pipeline — exactly the ICM skill's pattern of "every output is an edit surface."

## Shape

- **Card schema**: `{research_question, success_criteria, expected_output_shape, time_budget_minutes, capabilities_used: [cap-NNN, ...], acknowledged_at, acknowledged_by}`
- **Storage**: `/opt/data/scope-cards/<topic>-<timestamp>.md` (one per research run; **directory does not exist yet** — future per PROTOCOL.md Phase 1 §Hand-off artifact pattern)
- **Acknowledgment**: explicit (the user pastes `ack` into the chat) OR implicit-timeout (the workflow auto-aborts after 30 min if no ack)
- **Bypass**: only for cron jobs whose prompt has been pre-approved (the icm-weekly-digest cron prompt contains an embedded mini-scope card already)

Citations:

## Connected to

- **owns:** the pre-research gate; the `/opt/data/scope-cards/` directory; the ack-timeout behavior
- **owned-by:** nothing
- **joins:** `cap-011` (Interactive suspend/resume — extends the scope-card pause into mid-pipeline gates); `cap-012` (Automated claims verification — runs at the end of the run, vs. cap-010 at the start)
- **looks-like-but-is-not:** the NotebookLM notebook question field (that's a prompt for the LLM, not a gate for the user)

## If you change this

- **Hits:** every research workflow that doesn't have an embedded mini-scope card in its cron prompt; the scope-card storage directory; the acknowledgment CLI/chat pattern; the auto-abort timeout
- **Does not hit:** pure cron jobs whose prompt already includes the scope (e.g. `icm-weekly-digest` already has a hardcoded query in jobs.json — that *is* its scope card); `cap-014` (shadow agent CRUD — operates on its own notes, not research runs)
